## Purpose of this document

This file is loaded from the GitHub `notes` repo through the live sync path. If the deck shows this title, opens this body (not another post’s content), builds a multi-level TOC, and renders the diagram below without breaking the page, the pipeline is healthy.

1. Strict frontmatter at file head (not inside a code fence)

8. Bottom hashtag harvest into Indexed Topics

## Architecture of the stress path

The notes engine roughly follows:

```
Git tree → raw .md fetch → frontmatter extract → body parse → card meta → reader HTML
```

If any stage leaks state across posts (slug A with body B), this document is the canary: its title, image, and section names are unique on purpose.

### Sync boundary

Sync must bind **one** `{ slug, meta, content, rawContent }` object per file. Folder paths become slug prefixes (`test--hi` style). This file is intentionally flat under `posts/` so the slug stays predictable.

### Reader boundary

Opening this note must:

- Decrypt the real title (not a filename fragment)
- Prefer `meta` from sync over re-inferred filename titles
- Build TOC entries for every `##` / `###` below
- Leave particle/wind effects alone when clicking inside the reader chrome

## Failure modes this file is meant to expose

| Symptom | Likely layer |
|--------|----------------|
| Title shows filename-like “Pipeline Stress Test” only from slug | meta merge / re-parse |
| Body is another post’s text | cache generation or slug binding |
| No TOC | heading render or image `ReferenceError` abort |
| Date is 2026-05-31 | default meta winning over frontmatter |
| Category is a tag like `TEST` | category fallback order |
| Wind on reader click | effects ignore list |
